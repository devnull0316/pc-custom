# タスク: ディスプレイ着脱でのウィンドウ崩れを直す

`BRIEF.md` と `docs/RULES.md` を読め。
`docs/RESEARCH_FEATURES_ROUND4.md` の1位「ディスプレイ着脱・復帰時のウィンドウ崩れ自動修復」を実装する。

## 作るもの

外部ディスプレイを外した／スリープから復帰した後に崩れたウィンドウ配置を、**利用者が押したときだけ**戻す。

## 既にあるものを使う

`src-tauri/src/windows/window_placement.rs` に、必要なものがほぼ揃っている。
**再実装するな。** 読んで、足りない分だけ足せ。

- 同一セッションの窓の列挙、HWND 再利用の防御（PID + 生成時刻 + opaque HWND）
- ゲーム窓の除外、全画面判定、応答性の確認
- `WINDOWPLACEMENT` の保存と復元

`src-tauri/src/display_profile.rs` に表示構成の読み取りと比較がある。これも使え。

## 必ず守ること

- **自動で動かすな。** 崩れたことを検知して**知らせる**までが自動。戻すのは利用者が押したとき
- 戻す先は**保存済みの配置**。無ければ「戻す先がありません」と言え。推測で並べるな
- ゲーム窓・全画面・昇格した窓は対象外。**対象外なら理由つきで一覧に出せ**（黙って隠すな）
- 表示構成が保存時と違うなら、**そのことを先に言え**。違う構成へ機械的に戻さない
- ウィンドウタイトルをログにも EVIDENCE にも出すな

## 検証

**自分の窓だけで測れ。利用者の窓に触るな。**

`#[ignore]` の実機テストで:

1. 自分でテスト用の窓を作る
2. `WM_DISPLAYCHANGE` を待たずに済むよう、**保存済み配置と現在配置の差**を作る
3. 「崩れている」と判定されることを確認
4. 戻す
5. **`GetWindowRect` で読み直して**戻ったことを確認
6. ロールバックして、**もう一度読み直して**元へ戻ったことを確認

`EVIDENCE:` 行に前・崩れ後・戻し後・巻き戻し後の座標を並べろ。
**モニターが1枚しかないなら、着脱は測れない。その場合は `measured=false reason=...` と出せ。**
測れないことを合格にするな。
