# タスク: 画面の監査

`BRIEF.md` と `docs/RULES.md` を読め。**`docs/STATUS.md` は読まなくてよい。**

## 背景

利用者から実際に出た言葉は、**「大きさとか関係なく見にくい、わかりにくい、使いにくい」**
「項目多くて何が何だかって感じ」。

その後この数日で、画面に**パネルが7つ増えた**。
健全性レポート、タスクバー自動的に隠す、ホットコーナー、配色シーン、
画面共有の前と後、容量履歴、一時ワークスペース。

**元の不満が戻っている可能性がある。** そこを疑って見ろ。

## 見るもの

`src/components/*.tsx`、`src/styles.css`、`src/App.tsx`、`src/model.ts`。

### 1. どこに何があるか分かるか

- 増えたパネルが、**その画面の主目的を押しのけていないか**
- 同じ種類のものが別々の画面に散っていないか
- 「変更する」画面が、73項目＋パネル群で読めなくなっていないか
- 初めて開いた人が、最初に何をすればいいか分かるか

### 2. 密度と階層

- 1画面に詰め込みすぎていないか。**削れるものは何か**
- 見出しの階層が、実際の重要度と合っているか
- 折りたたみが多すぎて、中身に到達できなくなっていないか

### 3. 文字と色

- `styles.css` のフォントサイズが、意味のある段階になっているか
  （過去に .84/.86/.88rem のような1px以内の刻みを作って失敗している）
- 色のトークンが、意味で使い分けられているか。危険/警告/安全が一貫しているか
- 淡い文字が背景に埋もれていないか（**カードの背景と本文の差**も見ろ。文字色だけでない）

### 4. 言葉の一貫性

- 同じ操作が画面ごとに違う言葉になっていないか
  （「使う/やめる」「オン/オフ」「適用/実行」など）
- ボタンの文言が、押した結果を書いているか

### 5. 使えなさ

- 押せるものと押せないものが見分けられるか
- 待ち時間中に何が起きているか分かるか
- 失敗したとき、次に何をすればいいか書いてあるか

## 出し方

**具体的に。** 「改善の余地がある」ではなく、どのファイルのどこをどうするか。

FINDING
file: <repo相対パス>:<行番号>
quote: <その行の実際の中身をそのまま1行>
what: <何が使いにくいか。1文>
fix: <どう直すか。具体的に>
severity: high|medium|low
END

**引用する前に、その行が実在することを確かめろ。**
存在しない行を引く指摘が、このプロジェクトで最も多かった不良の形。

**数を稼ぐな。** 直す価値のあるものだけ。無ければ NO FINDINGS と書け。

## 厳守

- **コードを1行も変更するな。** 読んで報告するだけ
- 「モダンにする」「洗練させる」のような抽象的な提案をするな
- 新しいライブラリの導入を提案するな
