# タスク: 初回起動・失敗・空の状態を監査する

`BRIEF.md` と `docs/RULES.md` を読め。**`docs/STATUS.md` は読まなくてよい。**

## なぜ

これまでの監査は「動いているとき」しか見ていない。
**初めて開いた人**、**失敗したとき**、**まだ何も無いとき**は一度も見ていない。

## 見るもの

`src/App.tsx`、`src/components/*.tsx`、`src-tauri/src/bootstrap.rs`、`src-tauri/src/error.rs`。

### 1. 初めて開いたとき

- 記録が0件、モードが0件、セットアップ未実施。**その状態の画面はどう見えるか**
- 何をすればいいか分かるか。空の一覧に「まだありません」以上のことが書いてあるか
- 安全コアに繋がらない（catalog モード）とき、それが**利用者に伝わるか**
- 互換性ゲートで読み取り専用に倒れたとき、理由が読めるか

### 2. 失敗したとき

- エラーの文言が、**次に何をすればいいか**を書いているか
- 内部コード（`ACTION_...`、`E_...`、HRESULT）が画面に漏れていないか
- 「処理を完了できませんでした」だけで終わっている経路はないか
- 適用が途中で止まったとき、**何が変わって何が変わっていないか**が分かるか
- 復旧が必要な状態のとき、そこから抜ける道が画面にあるか

### 3. 待ち時間

- 押してから結果が出るまで、何が起きているか分かるか
- 押せない状態のボタンが、**なぜ押せないか**を伝えているか
- 長い処理（WinGet 導入、シェル再起動、一時ファイル削除）の途中経過が見えるか

### 4. 空・0件

- 0件の表示が「無い」なのか「読めなかった」なのか区別できるか
  （これは `docs/RULES.md` の中心的な規則）

## 出し方

FINDING
file: <repo相対パス>:<行番号>
quote: <その行の実際の中身をそのまま1行>
what: <何が問題か。1文>
fix: <どう直すか。具体的に>
severity: high|medium|low
END

**引用する前に、その行が実在することを確かめろ。**
**コードを1行も変更するな。** 数を稼ぐな。無ければ NO FINDINGS。
