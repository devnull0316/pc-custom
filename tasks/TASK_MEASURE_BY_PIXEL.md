# タスク: UIAで測れなかったものを、ピクセルで測る

`BRIEF.md` と `docs/RULES.md` を読め。
`docs/DISPLAY_ONLY_TRIAGE.md` の「保留」5件のうち、**タスクバーに現れるもの**を測る。

## 前提

UIA では測れなかった。**それは観測手段が無いという意味ではない。**
`ui_probe.rs` の `appearance_transparency_write_changes_taskbar_pixel_variance` は、
**タスクバーのピクセルを比べて透明度の効果を実測できている。** この型が既にある。

`taskbar_pixel_stats()` を読め。**再実装するな。**

## 対象

`taskbar.button_grouping`（ボタンのまとめ方）を最優先。
タスクバーの見た目が変わる設定なので、**ピクセルなら差が出るはず**。

余裕があれば、同じ手が使える他の保留項目も。

## 測り方

1. 同じアプリを2つ以上起動する（メモ帳など。**終了時に必ず閉じろ**）
2. `taskbar_pixel_stats()` で現在のタスクバーを記録
3. 設定を**今と違う値**へ書く
4. **シェル再起動が要るならする。** ただし
   - 再起動後に**タスクバーが戻ったことを必ず確認しろ**（このプロジェクトで実際に消したことがある）
   - 戻らなければ `measured=false` を出し、復旧を試みてから終われ
5. もう一度ピクセルを記録して比べる
6. 設定を戻し、シェルを再起動し、ピクセルを再記録

## 判定

- **ピクセルが有意に変わった** → 昇格候補として報告（昇格まではしなくてよい）
- **変わらなかった** → 「実測して効かない」へ格上げ。ただし
  **ピクセル差の閾値が妥当かを先に確かめろ**。
  既知の変化（アプリを1つ増やす等）で差が出ることを確認してから、
  「変わらなかった」と言え。**落ちない計器の合格には意味がない**
- **測れなかった** → `measured=false reason=...`。保留のまま

## 絶対に守ること

- 起動したアプリは必ず閉じろ。`Drop` を使え
- 設定は必ず戻せ
- **終了時にタスクバーが存在することを確認しろ**
- ウィンドウタイトルを出すな
