# タスク: 配色シーン

`BRIEF.md` が契約。`docs/STATUS.md` を読むこと。
自分が書いた `docs/RESEARCH_FEATURES_ROUND2.md` の「候補5」を実装する。

## 作るもの

「集中」「夜」「会議」のような名前から選ぶと、既にある3つの項目をまとめて適用する。

対象は**既に mutable として検証済みの3つだけ**。

- `theme.color_mode`
- `appearance.transparency`
- `appearance.window_color`

## 新しい Windows API を足さない

**これがこの候補の性質。** 自分でそう書いた。
新しい書き込み経路を作らない。既にある3つの Action を、既にある preview → commit で流すだけ。

- `.theme` ファイルの読み込みをしない
- 未文書のレジストリを触らない
- シーンが独自に隠れた状態を持たない

## 必ず守ること

- **部分失敗は、成功した分だけ元へ戻す。** 全部成功したことにしない。
  既存の preview → commit がそれをやっている。**自前の適用ループを書かない。**
- 途中で利用者が Windows の設定から同じ値を変えたら、既存の競合検出に任せる。
  上書きしない。
- **色見本は概算だと書く。** 全アプリが同じ色になるとは書かない。
- 「true black」「全アプリ統一」「時間帯の完全自動化」を約束しない。
  自分の調査文書にそう書いた。

## シーンの中身

3〜4個。名前は結果で。既定値を押し付けない。
シーンを選んでも**すぐには適用しない**。プレビューを出して、利用者が押したときだけ適用する。

## 画面

新しい画面を作らない。「変更する」画面の appearance カテゴリの中に置く。
Action として項目一覧に増やさない。**シーンは Windows の設定ではなく、既存項目の束ね方**。

## 検証

- シーンが**登録済みの3つの Action ID しか含まない**ことをテストで固定する。
  ここが緩むと、シーン経由で検証していない項目が適用される。
- シーンが `parametersForAction` と同じ形の引数を作ることを固定する。
- 文言に「true black」「すべてのアプリ」「必ず」が入らないことをテストで固定する。

実機テストは不要。既存 Action の実機検証が既にある。
**ただし「シーン経由でも既存の journal に1件ずつ残る」ことは確認すること。**
