## 作るもの

`docs/RESEARCH_FEATURES_ROUND2.md` を新規に書く。**6件から8件。**
上の9件と重ならない領域を探すこと。

### 今回とくに探してほしいもの

1回目は実用一辺倒だった。今回は**半分を「面白い」側に割く**こと。
ただし面白さを口実に BRIEF の制約を緩めない。

- **使っていて嬉しい・気が利いている**と感じるもの。
  作業を速くするのではなく、**PC が自分の道具だと感じられる**方向。
- 実用側は、**表示専用39件のうち「実は変更できる」ものが無いか**を疑ってほしい。
  読み取り専用に落とした理由が、当時の調査不足であるものが混ざっている可能性がある。
- **すでにある機能の組み合わせで生まれる価値**も候補にしてよい。
  新しい Windows API が要らないなら、それは実装が安く確実ということ。

### 各件について書くこと（1回目と同じ7項目）

1. 何ができるようになるか（**利用者の言葉で。** 設定名や API 名を使わない）
2. なぜ必要か（**実在する声を URL と日付つきで。** 票数や反応数も書く）
3. 既存ツールはどうしているか、なぜ足りないか（PowerToys、Windhawk、その他）
4. Windows のどの公開手段で実現できるか（**文書化された API の URL を貼る**）
5. 元に戻せるか（戻せないなら、そう書く。戻せるふりをしない）
6. 実装の難しさと、いちばん危ないところ
7. この製品の芯と噛み合う理由

## 絶対に守ること

- **需要の強さを盛らない。** 票数が小さいなら「需要強度は限定的」と書く。
  1回目でそう書けていたのは良かった。同じ正直さを保つこと。
- **効果を約束しない。** 「速くなる」「FPS が上がる」「入力遅延が減る」は書かない。
- BRIEF の禁止事項（Defender・ファイアウォール・Windows Update を止める、
  昇格、pagefile、HPET/BCD、サービス一括停止、アンチチート監視下への注入、
  ゲームファイルの改変、未知バイナリの実行）に触れる案は**最初から出さない**。
- 元に戻せない変更は、**戻せないと明記**したうえで、guided（設定画面へ案内）に落とす。
- 実装しない判断（保留・却下）も**理由つきで書く**。1回目の「今回は提案しないもの」と同じ形で。
