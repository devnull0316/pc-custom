# タスク: 表示専用39件を、測れるものと測れないものに仕分ける

`BRIEF.md` と `docs/RULES.md` を読め。

## 分かっていること

表示専用は 39 件。しかし `src-tauri/src/windows/ui_probe.rs` にある効果測定は**約12本**。

つまり **10件ほどは「実測して効かないと確認済み」**、
**残り約29件は「測っていないだけ」**。この2つが同じ「表示専用」として並んでいる。

`docs/RULES.md` の「**分からないものを断定に混ぜない**」に自分たちで違反している。

## やること（測定はまだするな。仕分けだけ）

`src-tauri/src/action/registry.rs` から `MethodClass::UnverifiedStorage` の Action を全部挙げ、
1件ずつ次を判定して**表にしろ**。

| Action ID | 実測済みか | 測るなら何を見るか | 難易度 |

- **実測済みか**: `ui_probe.rs` にその Action の効果を測るテストが**実在するか**。
  テスト名だけで判断するな。**中身を読んで、その Action の効果を見ているか**確かめろ
- **測るなら何を見るか**: 外から観測できる具体的な対象。
  「エクスプローラーの一覧に拡張子が出るか」「タスクバーのボタンの有無」のように、
  **UIAかピクセルか別プロセスの読み取りで確かめられる形**で書け
- **難易度**: 小（既存のプローブの型をそのまま使える）／中（新しい観測が要る）／
  **不可**（外から観測する手段が無い。理由を書け）

## 重要

- **「たぶん効く」で昇格候補にするな。** 観測方法が書けないものは「不可」
- 既に「効かない」と実測済みのものは、**その証拠がどこにあるか**（STATUS.md の節など）を書け
- 39件全部を表に載せろ。**1件も飛ばすな。** 飛ばすなら理由を書け

## 成果物

`docs/DISPLAY_ONLY_TRIAGE.md`。上の表と、末尾に:

- 実測済み（効かないと確定）: N件
- 測れる見込み（小）: N件 ← **次に測る候補**
- 測れる見込み（中）: N件
- 測る手段が無い: N件

**コードを1行も変更するな。文書だけ。**
