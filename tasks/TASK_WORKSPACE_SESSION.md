「終わる」で、**このアプリが動かしたものだけ**を元へ戻す。

## Action を増やさない

**71件のまま。** これは新しい設定ではなく、既にある可逆 Action の束ね方。
自分でそう書いた。`ActionId` を足さないこと。

束ねてよいのは、**既に mutable として実機検証済みの Action だけ**。
どれを含めるかは利用者が明示的に選ぶ。既定で全部入れない。

## 言葉

**「終わる」はアプリを閉じることではない。** 窓と設定を戻すだけ。
画面に「窓と設定を戻します。アプリは閉じません」と明記すること。

「PC を開始前の状態へ巻き戻す」とは書かない。戻すのは**このアプリが動かした分だけ**。

## 必ず守ること

### 自前の適用ループを書かない

既存の preview → commit → journal を通す。
**部分失敗の扱いも、逆順ロールバックも、既存が持っている。** 作り直さない。

### 同じに見える別の窓を戻さない

最大のリスクは、同じタイトル・同じ実行ファイルの**別の窓**を動かすこと。
`src-tauri/src/windows/window_placement.rs` に、
PID・プロセス生成時刻・opaque HWND を突き合わせる本人性の判定が既にある。**それを使う。**

開始時に捕捉できた窓だけを扱う。セッション中に新しく開いた窓は対象外。

### 外部変更を上書きしない

セッション中に利用者や他アプリが動かした窓は、**戻さずに「外部変更」として残す**。
理由を画面に出す。黙って上書きしない。

### アプリを強制終了しない

未保存の文書があるかは判断できない。**閉じない。** 起動もしない
（既に許可されている `setup.launch_apps` の経路を使う場合を除く）。

## 検証（ここが本題）

自分で書いた「8) 外から効いたとどう測るか」をそのまま実行すること。

`#[ignore]` の実機テストで、**別プロセスの窓**を使って測る。

1. テスト用の別プロセスで標準の窓を2つ以上作る
2. 開始前の画面座標と表示状態を記録する
3. セッションを適用する
4. **窓の側から読み直して**、期待した位置にあることを確認する
5. **セッション中に1つの窓を人為的に別位置へ動かす**
6. 終了する
7. 動かさなかった窓が元へ戻り、**人為的に動かした窓は上書きされず「外部変更」として残る**ことを確認する

`EVIDENCE:` 行に、各時点の全窓の座標を出すこと。
panic しても窓を破棄するよう `Drop` を使う。**利用者の窓に触らない。**
