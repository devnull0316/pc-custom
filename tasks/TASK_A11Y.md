# タスク: キーボードと支援技術で使えるようにする

`BRIEF.md` と `docs/RULES.md` を読め。**`docs/STATUS.md` は読まなくてよい。**

## なぜ

これは **Windows の設定を変えるアプリ**で、利用者には
キーボードだけで操作する人、画面読み上げを使う人が含まれる。
固定キー機能の Action を持っているのに、アプリ自身が使えないのでは筋が通らない。

## やること

`src/components/*.tsx` と `src/styles.css` を直す。**Rust には触るな。**

### 1. キーボードだけで一周できるか

- Tab で全ての操作可能要素へ到達できるか。**到達できない操作を無くす**
- フォーカスの見える化（`:focus-visible`）が全てのボタン・リンク・入力にあるか
- ダイアログを開いたらフォーカスが中へ入り、Esc で閉じ、閉じたら元へ戻るか
- 折りたたみ（`aria-expanded`）とタブ（`role="tablist"`）がキーで操作できるか

### 2. 読み上げで意味が通るか

- アイコンだけのボタンに `aria-label` があるか
- 状態の変化（適用中、完了、失敗）が `aria-live` で伝わるか
- 一覧・表・見出しの階層が構造として正しいか（`h1` が複数ないか等）
- 装飾のアイコンが `aria-hidden` になっているか

### 3. 目で見て分かるか

- **色だけで意味を伝えていないか**（危険/安全を色だけで区別していないか）
- フォーカスリングのコントラストが背景に対して足りているか

## 絶対に守ること

- **見た目を大きく変えるな。** 直すのは到達性と読み上げ
- 新しいライブラリを入れるな
- `npm run build` の CSS 構文警告を**0件のまま**保て

## 検証

**直したと言うな。測れ。**

`src/` に対して、次を機械的に数えて**前後の数字を報告に出せ**。

- アイコンのみのボタンで `aria-label` が無いもの の件数
- `onClick` を持つ非ボタン要素（`div`/`span`）の件数
- `:focus-visible` を持たない対話要素のセレクタ数
- `h1` の個数（画面あたり1つか）

前後で数字が改善していること。**0件になったと言うだけでは足りない。数え方も一緒に出せ。**
