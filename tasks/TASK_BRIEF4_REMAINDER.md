# タスク: BRIEF §4 の残り3機能

`BRIEF.md` が最上位の契約。この指示書と矛盾したら BRIEF が勝つ。

対象は BRIEF §4 のうち未実装の3つ。

1. 既定アプリ設定の案内
2. ウィンドウ配置の保存・復元
3. 音声出力先の切り替え

## 先に伝えておく判断（調べ直してよいが、覆すなら実機の証拠を出すこと）

このプロジェクトで最も高くついた失敗は、**レジストリに値を書けたので動いたことにした** Action を6つ
出荷し、あとから UI Automation で読んで「Windows は一切従っていなかった」と判明したことだ。
テストは全部緑だった。緑のテストは「意図した値を書けた」ことしか証明しない。

だから今回も、**実機で効果を観測できないものは Action として出荷しない**。

### 1. 既定アプリ — おそらく Guided が正解

Windows 11 の既定アプリは `UserChoice` にハッシュ保護がかかっていて、
文書化された手段でプログラムから変更する方法がない。ハッシュを偽造する類の回避は
BRIEF の禁止事項（文書化されていない内部仕様への依存）に真正面から触れる。**やらない。**

`ms-settings:defaultapps` を開く Guided Action にする。既存の `settings_link.rs` の仕組みに乗せる。
UI では「Windowsの仕様で、ここから直接は変更できません」と正直に書く。ごまかさない。

### 2. ウィンドウ配置 — これは本物として作れるはず

`EnumWindows` / `GetWindowPlacement` / `SetWindowPlacement` / `GetWindowRect` は公開APIで、
プロセスへの注入ではない。これは実装してよい。ただし:

- **ゲームのウィンドウは対象外にする。** アンチチート製品が別プロセスからのウィンドウ操作を
  どう見るかは我々が保証できない。BRIEF の禁止事項に近づかない。
- 保存するのは「ユーザーが今開いているウィンドウの位置」であって、勝手に集めるものではない。
  保存は明示操作にする。
- 復元時、対象ウィンドウが存在しなければ静かに飛ばすのではなく、**何を復元できなかったか返す**。
- 最小化・最大化状態も `WINDOWPLACEMENT.showCmd` で保存・復元する。
- ウィンドウタイトルはユーザーの個人情報を含みうる（ファイル名、メールの件名）。
  **ログには出さない。** 保存データに入れるのは避けられないが、ログ・エラーメッセージには出さない。

### 3. 音声出力先 — おそらく Guided が正解

既定の再生デバイスを変える公式APIは公開されていない。世に出回る方法は `IPolicyConfig` という
**非公開COMインターフェース**で、Windows のビルドごとに壊れうる。BRIEF が禁じている類のものだ。**使わない。**

`MMDeviceEnumerator`（公開API）で**デバイス一覧と現在の既定を読む**のは正当なので、
「今どのデバイスに出力されているか」は本当に表示できる。表示は本物、切り替えは
`ms-settings:sound` への案内、という組み合わせにする。読み取りが本当に動くことは実機で確認すること。

## 必須の作法（過去に全部やらかしている）

- TODO を残して完了扱いにしない。モックを本番経路に混ぜない。エラーを握りつぶさない。
- ユーザー入力をシェル文字列へ連結しない。プロセスは直接起動、引数は固定 Vec。
- Action ごとに単体テスト。変更を伴うものは apply → detect → rollback → detect まで。
- Guided は `validate` の時点で変更を拒否する。既存の `explorer_visibility.rs` の実装と
  `demoted_actions_refuse_to_mutate` テストが手本。同じ形で新しい Guided もテストで固定する。
- 日本語UI。設定名ではなく結果で書く。「ShowSecondsInSystemClock を有効化」ではなく
  「タスクバーの時計に秒を表示する」。
- 「爆速」「ゼロ遅延」の類は書かない。「安全」と言い切らない。
- `cargo test --lib`（現在196件）と `npm run build` が両方通る状態で終わること。

## 完了報告に必ず含めること

- ウィンドウ配置を**実機で**保存→動かす→復元して、位置が戻ったことをどう確認したか
- 音声デバイスの読み取りが**実機で**何を返したか（デバイス名は伏せてよい、件数と既定の有無）
- Guided にしたものについて、なぜ実装ではなく案内なのか、上の判断に同意したのか
