# タスク: 「フォルダーを別プロセスで開く」を昇格できるか、証拠で決める

`BRIEF.md` が契約。`docs/STATUS.md` を読むこと。
自分が書いた `docs/RESEARCH_FEATURES_ROUND2.md` の「候補3」を進める。

## この作業の性質

**いきなり Action を作らない。** 作るのは**検証**。

`SHGetSetSettings` は戻り値が `void`。**呼べたことは成功の証明にならない。**
自分でそう書いた。だから最初に作るのは「効いたかどうかを外から言えるか」の確認。

いま `explorer.separate_process` は表示専用（39件のうちの1つ）。
昇格してよいかは、以下の証拠鎖が通った場合にだけ決まる。

## 作るもの

### 1. 読み取り（`src-tauri/src/windows/` へ）

`SHGetSetSettings` に `SSF_SEPPROCESS` を渡し、`bSet=FALSE` で `fSepProcess` を読む。
**読み取りだけの関数を先に作る。** 書き込みはその次。

### 2. 書き込み

`bSet=TRUE` で書く。ただし**戻り値を信用しない。** 書いたあと必ず読み直す。

### 3. 外からの確認（ここが本題）

読み直して値が変わっただけでは「別プロセスで開くようになった」とは言えない。
それは設定値が変わっただけ。**実際に窓が別プロセスで開くかを外から見る。**

やり方は任せるが、次の性質を満たすこと。

- 自分で開いたフォルダー窓だけを対象にする。**利用者の窓を数えない。**
- 開いた窓のプロセス ID を `GetWindowThreadProcessId` で取る。
- 設定オフのときと設定オンのときで、**プロセス ID の出方が違うことを数値で示す。**
- 開いた窓は必ず閉じる。`Drop` を使う。

**この確認ができないなら、できないと結論して昇格しない。** それも成果。
`docs/STATUS.md` に「エクスプローラー系の候補は現時点では測れない」という前例がある。
同じ結論になっても構わない。**測れないものを測れたことにしないこと。**

## 必ず守ること

- 検証中に変えた設定は、**必ず元へ戻す。** panic しても戻るよう `Drop` を使う。
- 利用者の Explorer 窓を閉じない。自分で開いたものだけ閉じる。
- 「クラッシュしなくなる」「メモリリークが直る」とは書かない。
  自分の調査文書にそう書いた。Insider build で Explorer が開かなくなった報告もある。
- registry を直接書かない。UI Automation で設定画面のチェックボックスを押さない。

## 結論の書き方

`docs/STATUS.md` の末尾に節を足して、次を書くこと。

- 何を測ったか
- 数値（`EVIDENCE:` 行をそのまま貼る）
- **昇格してよいか、してはいけないか、まだ分からないか**
- そう判断した理由

昇格してよいという結論が出た場合にだけ、Action の実装へ進む。
出なかった場合は**実装しない。** 表示専用のままにして、理由を書く。
