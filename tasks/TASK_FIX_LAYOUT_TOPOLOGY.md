# タスク: 配置の適用時に、表示構成の一致を確かめる

`BRIEF.md` と `docs/RULES.md` を読め。

## 直すもの

`src-tauri/src/actions/window_layout.rs:380` 付近。

`apply` は状態の fingerprint が前提と一致するかは見ているが、
**保存時と現在の表示構成が同じかを見ていない。**

`display_rescue` は「構成が違う」と報告するが、Action 自体は止まらない。
つまり **2画面で保存した配置を1画面へ機械的に適用できてしまう。**
座標は保存時の画面を前提にしているので、窓が見えない場所へ行く。

## どう直すか

- 保存された配置に表示構成が記録されているなら、`apply` の前に現在と突き合わせろ
- 違うなら **`ExternalConflict` ではなく専用のエラー**で止めろ。
  第三者が変えたのではなく、画面構成が変わったという別の事実
- 文言は利用者の言葉で。「画面の構成が保存したときと違います」の線
- 表示構成が**記録されていない古い配置**は、推測するな。
  そのことを言って止めるか、利用者が明示的に押したときだけ通すか、**どちらかに決めて理由をコメントに書け**

`src-tauri/src/display_profile.rs` の `compare_topology` を使え。**再実装するな。**

## 検証

単体テストで固定しろ。**実機の画面数に依存させるな。**

1. 保存時と現在で構成が同じ → 通る
2. 構成が違う（画面数／解像度／座標）→ **止まる。座標を1つも書かない**
3. 表示構成の記録が無い古い配置 → 決めた挙動になる
4. **止まったとき、窓が1つも動いていないこと**

`compare_topology` を「常に一致」に潰したら、2 のテストが落ちること。
落ちないなら、そのテストは何も見ていない。
