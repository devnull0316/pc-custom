# タスク: いまのPCの状態を1枚にまとめて、あとで照合する

`BRIEF.md` と `docs/RULES.md` を読め。
`docs/RESEARCH_FEATURES_ROUND4.md` の3位「マイPCカスタムカード」を実装する。

## 作るもの

いまの全項目の状態を1枚のカードとして書き出し、あとで**いまの状態と照合**する。

## 既にあるもの（重複させるな）

- `src-tauri/src/config_snapshot.rs` — 現在状態の書き出しが**既にある**
- `src-tauri/src/health_report.rs` — 適用済み設定の照合が**既にある**

**この2つを作り直すな。** 足りないのは、
1. 書き出したカードを**あとで読み込んで、そのときの状態と突き合わせる**こと
2. その差を人が読める形で見せること

`health_report` は「このアプリで適用したもの」だけを見る。
カードは「**全項目**の、ある時点の姿」を見る。ここが違う。

## 必ず守ること

- **カードはデータだけ。** コードもコマンドも含めない。読み込んでも何も実行しない
- 読み込んだカードは**適用しない。** 照合して見せるだけ。適用は既存の preview → commit を通す
- 差があっても**原因を断定するな**（`docs/RULES.md`）。「違います」まで
- **確認できない項目を「同じ」に混ぜるな。** 別の欄に出し、件数にも現れるようにしろ
- カードを作った時点と今で**Windowsのビルドが違う**なら、それを先に言え
- 個人情報を入れるな。パス・ユーザー名・ファイル名・ウィンドウタイトルは出さない
- 他人のカードを読み込む可能性がある。**信用できない JSON として扱え。**
  壊れた JSON、巨大な配列、知らない項目 ID で破綻しないこと

## 検証

**単体テストで固定しろ。**

1. カードに無い項目・今に無い項目が、それぞれ正しい欄に入ること
2. 確認できない項目が「同じ」に混ざらないこと
3. 原因を断定する文言が出ないこと（文言のテスト）
4. 壊れた JSON・知らない項目 ID で panic せず、拒否すること
5. **カードを読み込んでも Windows が一切変わらないこと**
