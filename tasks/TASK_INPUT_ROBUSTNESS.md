# タスク: 想定外の入力に対する頑健さを見る

`BRIEF.md` と `docs/RULES.md` を読め。**`docs/STATUS.md` は読まなくてよい。**

## なぜ

このアプリは自分のPCの設定を書き換える。入力の検証が甘いと、
**利用者が意図しない場所を書き換えたり消したりする**。壊れ方の話であって、
攻撃の話ではない。壊れないことを確かめたい。

## 見るもの

1. **境界の検証**
   - `src-tauri/src/commands.rs` の各コマンドが受け取る文字列・数値・パス。
     長さ・文字種・範囲の検証はどこで行われているか。抜けはあるか
   - 検証を通らずに Windows API やファイル操作へ届く値はあるか

2. **取り込むファイル**
   - `src-tauri/src/config_snapshot.rs` の取り込みが、壊れた JSON、
     極端に大きい配列、深いネストで破綻しないか
   - 取り込んだ値がそのまま画面や API へ流れていないか

3. **パスの扱い**
   - パスを組み立てている箇所で、`..` や絶対パスの混入を弾いているか
   - 一時ファイル削除と設定ディレクトリが、リンクを辿って
     **意図しない場所を消す**可能性はないか

4. **起動する実行ファイル**
   - パスがどう決まるか。作業ディレクトリや `%PATH%` に依存していないか

5. **記録に残る個人情報**
   - ログ・エラー・耐久記録に、ファイル名・ウィンドウタイトル・
     ユーザー名・接続先・プリンター名が漏れていないか

## 出し方

FINDING
file: <repo相対パス>:<行番号>
quote: <その行の実際の中身をそのまま1行>
what: <どう壊れるか。1文>
how: <どんな入力・環境でか。具体的に>
severity: high|medium|low
END

**引用する前に、その行が実在することを確かめろ。**
**コードを1行も変更するな。** 無ければ NO FINDINGS。
