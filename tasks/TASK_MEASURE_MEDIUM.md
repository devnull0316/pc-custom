`BRIEF.md` と `docs/RULES.md` を読め。
`docs/DISPLAY_ONLY_TRIAGE.md` の難易度「中」の項目を測る。**21件ある。**

## 直前の失敗から学べ

`explorer.launch_target` は一度「実測して効かない」と結論された。
観測に `explorer.exe /n`（引数付き）を使っていて、**設定が効く経路を通していなかった。**
引数なしで測り直したら効いた。いま昇格して使えるようになっている。

**同じ間違いをするな。** 各項目について、まず
「**この設定は、どの操作をしたときに効くのか**」を確かめてから観測方法を決めろ。
効かない経路を観測して「効かない」と書くのが、いちばんもったいない。

## 進め方

**一度に全部やるな。** 3〜5件ずつ、確実に測れ。今回は**最初の5件**でよい。

各項目について:

1. その設定が効く操作は何か（新しい窓を開く？ シェル再起動が要る？ 再ログオン？）
2. その操作を経た状態を、**別プロセスから**観測する
3. 今と違う値を書く → 観測 → 戻す → 再観測
4. 判定:
   - 変わった → **昇格候補**として報告（この作業では昇格まではしなくてよい）
   - 変わらなかった → 「実測して効かない」へ格上げ
   - シェル再起動や再ログオンが要る → **その条件を明記**して、
     再起動なしでは効かないことを実測として残せ
   - 観測できなかった → `measured=false reason=...` を出し、難易度を「不可」へ直せ

## 絶対に守ること

- **利用者の設定を戻せ。** `Drop` を使え。panic しても戻せ
- ウィンドウタイトル・ファイル名を出すな
- **「たぶん効く」で昇格候補にするな。** 観測が変わったことだけが根拠
- シェル再起動を伴う測定では、**終わったらタスクバーが戻っていることを確認しろ**
  （このプロジェクトで実際にタスクバーを消したことがある）
