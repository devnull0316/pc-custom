# タスク: この製品のデザインを把握し、改善点を調べる

`BRIEF.md` と `docs/RULES.md` を読め。

## 段階1: いまのデザインを把握する（自分で読む）

`src/components/*.tsx` 全22ファイル、`src/styles.css`、`src/App.tsx`、`src/catalog.ts` を読み、
**この製品のデザインが今どうなっているかを自分の言葉でまとめろ。**

- 画面は何枚あり、それぞれ何のためにあるか
- 情報の階層（何が主で何が従か）
- 色・文字サイズ・余白のトークンがどう定義され、どう使われているか
- 繰り返し現れる部品（カード、パネル、空状態、状態表示）の型
- 利用者の導線（初めて開く → 何かを変える → 戻す）

`docs/DESIGN_LANGUAGE.md` があれば読め。無ければそう書け。

## 段階2: 外を調べる（web検索を使え）

この製品は **Windows の設定を安全に変え、1件ずつ元へ戻せる**ことが芯。
性能を上げる製品ではない。利用者は初心者を含む。

似た性質の製品・分野から、**実在する設計の作法**を集めろ。URLと日付を付けろ。

- OS の設定を変えるツールの UI（Windows 設定、System Settings、PowerToys、Rectangle 等）
- 「元に戻せる」ことを中心に据えた製品の見せ方（バージョン管理、写真編集の履歴、
  データベースのマイグレーションツール）
- 危険度のある操作を初心者に見せる作法（金融、医療、インフラの管理画面）
- 項目数が多い設定画面の整理のしかた（70件以上ある画面で実際に使われている手法）

## 段階3: 改善案を出す

**この製品の芯に沿うものだけ。** 「モダンにする」「洗練させる」は書くな。

各案について:

1. 何が良くなるか（利用者の言葉で）
2. いまどうなっていて、何が問題か（**ファイルと行を挙げろ。引用も付けろ**）
3. どう変えるか（具体的に。CSS の値、部品の構成、文言）
4. 根拠（段階2 で集めた実在の作法。URL と日付）
5. 実装の大きさ（小/中/大）と、壊しうるもの
6. **やらない理由があるならそれも書け**

6件から10件。**数を稼ぐな。**
