# タスク: 見失ったウィンドウを今の画面へ戻す

`BRIEF.md` が契約。`docs/STATUS.md` の失敗記録を先に読むこと。
自分が書いた `docs/RESEARCH_FEATURES.md` の「2. 見失ったウィンドウを今の画面へ戻す」を実装する。

## 作るもの

いま**どの画面にも出ていない窓**を一覧に出し、選んだ1つを今の画面へ戻す。
モニターを外した、電源を切った、負座標へ飛んだ、といった後に見えなくなった窓が対象。

**保存済みレイアウトの復元とは別機能にする。** あれは「保存した配置へ戻す」で、
これは「今どこにも見えていない窓を救う」。混ぜない。

## 既にあるものを使う

`src-tauri/src/windows/window_placement.rs` に、この作業に必要なものがほぼ揃っている。

- 自分と同じセッションの窓の列挙
- **HWND 再利用の防御**（PID + プロセス生成時刻 + opaque HWND の照合）
- ゲーム窓の除外
- 全画面判定（`is_fullscreen`）
- 応答性の確認（`WM_NULL` + `SMTO_ABORTIFHUNG`）
- `WINDOWPLACEMENT` の保存と復元

**再実装しないこと。** 既存を読んで、足りない分だけ足す。

## 判定条件

「見えていない」を、次のどちらかで定義する。**推測で広げないこと。**

1. 窓の矩形が、いま接続されている**どのモニターの作業領域とも重ならない**
2. 重なっているが、重なりが極端に小さい（例: 面積の1割未満）

`MonitorFromRect` に `MONITOR_DEFAULTTONULL` を渡すか、`EnumDisplayMonitors` で
全モニターの矩形を集めて自分で判定する。どちらでもよいが、**なぜその判定にしたかをコメントに書くこと。**

## 必ず守ること

- 動かすのは**利用者が一覧から選んだ1つだけ**。まとめて動かす機能は作らない
- ゲームの窓、全画面の窓、system UI、cloaked / tool / owned window は対象外
- 昇格した窓は動かせない。**動かせないなら一覧に出したうえで理由を書く**（黙って隠さない）
- 動かす前に `WINDOWPLACEMENT` と矩形と本人性（PID・生成時刻）を保存し、**元へ戻せるようにする**
- 戻すとき、対象が別プロセスに入れ替わっていたら触らない
- **ウィンドウタイトルはログにもエラーにも出さない。** 個人情報を含む。既存の redact の作法に従う

## 検証（ここが本題）

**自分の窓だけで測ること。利用者の窓に触れない。**

`#[ignore]` の実機テストを書く。

1. 自分でテスト用の窓を作る
2. 画面外の座標（例: 負の大きな値）へ移動させる
3. 「見えていない窓」として検出されることを確認する
4. 今の画面へ戻す
5. **`GetWindowRect` で読み直して**、画面内に入ったことを確認する
6. 元の位置へロールバックする
7. **もう一度読み直して**、元の座標に戻ったことを確認する

`EVIDENCE:` 行に、移動前・画面外・救出後・戻し後の座標を並べること。
panic しても窓を破棄するよう `Drop` を使う。
