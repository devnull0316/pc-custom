# タスク: このアプリに足すべき機能の調査

`BRIEF.md` が最上位の契約。`README.md` と `docs/STATUS.md` に現状と、これまで踏んだ失敗が全部書いてある。
**先に読むこと。** 特に STATUS.md の「緑のテストは何も証明しない」系の記録は、
この製品の判断基準そのものなので、提案がそこに反していないか自分で確かめること。

## 何をしてほしいか

**調査だけ。この段階では実装しない。**

Windows 11 のカスタマイズ・設定支援まわりで、このアプリに足す価値がある機能を調べて提案する。
観点は3つ。

1. **需要がある** — 実際に多くの人が困っていて、既存の手段が面倒か存在しない
2. **足すべき** — この製品の芯（結果から選ぶ／全部1件ずつ元に戻せる／専門知識不要）と噛み合う
3. **面白い** — 他のツールがやっていない、あるいはやり方が新しい

## 調べ方

Web を使ってよい。次のような一次情報に当たること。

- Windows のカスタマイズについて人が実際に何を聞いているか
  （Reddit r/Windows11, r/pcmasterrace, Microsoft Community, 知恵袋, 5ch のまとめ等）
- 既存ツール（Winaero Tweaker, ExplorerPatcher, StartAllBack, Rainmeter, PowerToys,
  TranslucentTB, Wallpaper Engine, Nilesoft Shell, Files など）が何を提供し、
  **何を提供していないか**
- それらのツールの Issue や要望で、繰り返し出ているのに未実装のもの
- Windows 11 のバージョン更新で壊れた／消えた機能と、その代替を求める声

**「一般に良さそう」ではなく、出典を示せるものだけを挙げること。**
根拠のない思いつきは書かないでほしい。この製品は「根拠を示せない主張をしない」ことを売りにしている。

## 制約（BRIEF より。破る提案は出さないこと）

- Microsoft Defender / ファイアウォール / Windows Update を止める機能は入れない
- ページファイル無効化、HPET/BCD 変更、サービス一括停止はしない
- アンチチート対象プロセスへの注入、ゲームファイルの改変はしない
- 利用者が書いた任意の PowerShell やスクリプトを実行しない
- 出所不明のバイナリを落として実行しない
- 「FPS が上がる」等、根拠を示せない効果を謳わない
- **変更したものは1件ずつ元に戻せること。** 戻せない機能は原則入れない
  （どうしても不可逆なものは、不可逆だと明示して二段階確認する）
- 管理者権限で常駐しない

## 報告の形

`docs/RESEARCH_FEATURES.md` に日本語で書くこと。1案につき次を必ず含める。

1. 何ができるようになるか（**利用者の言葉で**。設定名や API 名で書かない）
2. なぜ必要か（**出典つき**。誰がどこで困っていると言っているか）
3. 既存ツールはどうしているか、なぜ足りないか
4. Windows のどの公開手段で実現できるか（文書化された API / 設定 / 公式 CLI のいずれか）
5. **元に戻せるか。** 戻し方まで書く。戻せないなら、そう書く
6. 実装の難しさ（小・中・大）と、いちばん危ないところ
7. この製品の芯と噛み合う理由

最後に「まず作るならこの3つ」を、理由つきで選んでおくこと。

## やらないこと

- コードを変更しない（調査のみ）
- 実現できるか不明なものを「できる」と書かない。**不明なら不明と書く**
- 出典のない主張を書かない
