# タスク: 画面の角にマウスを置くとモード確認を開く

`BRIEF.md` が契約。`docs/STATUS.md` を読むこと。
自分が書いた `docs/RESEARCH_FEATURES_ROUND2.md` の「候補4」を実装する。

## 作るもの

画面の角にマウスを一定時間置くと、PCカスタムの窓を前に出す。それだけ。

## 角に着いても Windows を変えない

**これが一番大事。** 角に着いたことで設定が変わってはいけない。

読み取りだけの項目は出してよい。変更できる項目は**プレビューを開くところまで**。
適用は利用者が押したときだけ。既存の preview → commit を必ず通す。

角の機能そのものは PCカスタムのアプリ内設定なので、Windows 側に戻す対象は無い。

## 既定は無効

**入れていない人には何も起きないこと。** 調査文書にも「Linux では最初に無効化する」という声を
自分で引いている。誤発火する機能を既定で有効にしない。

角ごとに「何もしない」を選べること。4つ全部が既定で「何もしない」。

## 誤発火を防ぐ

以下は**全部**入れること。1つでも欠けると邪魔な機能になる。

- **滞在時間**。触れた瞬間ではなく、一定時間そこに居続けたときだけ。既定は長めに。
- **クールダウン**。一度出したら、しばらくは出さない。
- **全画面のときは出さない。** `foreground_is_fullscreen()` が既にある。
  「分からないときは true」に倒す作りなので、この用途でもそのまま使える。迷ったら出さない。
- **最大化中も抑制するか**を決めて、理由をコメントに書く。
- **マウスが動いている最中は数えない。** 通り過ぎただけで出さない。
- **複数モニターの内側の角を対象にしない。** 画面の間を通っただけで出る。
  外周の角だけにする。`MonitorFromPoint` と `GetMonitorInfo` で判定する。

## 常駐

`GetCursorPos` の低頻度ポーリングで足りる。**global low-level mouse hook を入れない。**
既存の監視ループ（`src-tauri/src/game_profile/watcher.rs`）に相乗りしてよいが、
角の判定はもっと短い間隔が要るなら別スレッドにしてよい。**CPU を測って報告すること。**

## 画面

新しい画面を作らない。モード画面（`src/components/ProfilesView.tsx`）の中に置く。
Action として項目一覧に増やさない。これは Windows の設定ではない。

## 検証

**「実装した」を「誤発火しない」の証明にしない。**

純関数として判定を切り出し、単体テストで次を固定すること。

1. 滞在時間に満たないと発火しない
2. 通り過ぎ（座標が動き続けている）では発火しない
3. 一度発火したらクールダウン中は発火しない
4. 全画面のときは発火しない
5. 複数モニターの内側の角では発火しない
6. 既定（すべて「何もしない」）では、どこに居ても何も起きない

実機テストは `#[ignore]` で、`GetCursorPos` が読めることと、
主モニターの外周の角の座標が正しく出ることを `EVIDENCE:` 行に出すこと。
**利用者のマウスを勝手に動かさない。**
