# タスク: ピクセル計器の感度を上げて、もう一度測る

`BRIEF.md` と `docs/RULES.md` を読め。

## 分かっていること

`taskbar.button_grouping` は2つの方法で測れなかった。

1. **UIA** — タスクバーのボタンが要素として露出しない
2. **ピクセル平均** — 幅の5〜95%に200点を散らして平均するので、
   ボタン2個の増減が埋もれる。**校正で `known_change_delta=0.0000` と出た**

計器が鈍いのであって、変化が無いのではない。**メモ帳2つでタスクバーは目に見えて変わる。**

## やること

**中央付近に絞った比較**を作る。`taskbar_pixel_stats()` は既存のまま残せ（透明度が使っている）。
新しい関数を足せ。

観測の候補（**どれか1つで良い。効くものを選べ**）:

- タスクバー中央付近の**横一列**を細かく（200点ではなく、1px刻みで数百点）読み、
  **色が変わる境界の数**を数える。ボタンが増えれば境界が増える
- 中央 40% だけを対象に、**分散**を見る（平均ではなく）
- 左端から中央にかけての**輝度の変化パターン**を配列で持ち、配列同士を比べる

## 手順（必ずこの順）

1. **まず校正しろ。** メモ帳0個 → 2個 で、新しい計器が**差を出すか**確かめる
2. 差が出なければ、**別の観測に変えてもう一度校正**しろ。
   3回変えても出なければ `measured=false reason=..._insensitive` を出して止めろ。
   **鈍い計器で「効かない」と言うな**
3. 校正が通ってから、初めて設定を測れ

## 判定

- 校正が通り、設定変更で差が出た → **昇格候補**として報告
- 校正が通り、設定変更で差が出なかった → 「実測して効かない」へ格上げ
- 校正が通らない → 保留のまま。試した観測方法を記録しろ

## 絶対に守ること

- 起動したメモ帳は必ず閉じろ。`Drop` を使え
- 設定は必ず戻せ
- シェル再起動をするなら、**終了時にタスクバーが存在することを確認しろ**
- `EVIDENCE:` 行に**校正の数値**を必ず含めろ
