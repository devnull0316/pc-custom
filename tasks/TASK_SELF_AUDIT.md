## 探すもの

**「動くこと」ではなく「約束を破っていないこと」を疑う。**

### 1. 戻せると言って戻せないもの

- `create_backup` が、ロールバックに要るものを全部保存しているか
- ロールバックが**元の値**へ戻しているか。既定値を書いていないか
- 第三者が変えた状態を上書きしていないか
- 2回に分けて書く処理で、片方だけ通ったまま返る経路が無いか
- プロセスが強制終了されたとき、残るものが無いか

**この形の不具合を直近で1件出荷している。**
タスクバーの自動的に隠すで、戻す先を `false` と決め打ちにしていた。
元から「常に隠す」にしている人の設定を、黙って解除して二度と戻さなかった。
**同じ形が他に無いか、全部見ること。**

### 2. 名前と中身が違うテスト

**直近で3件見つかっている。**

- 「bit と作業領域の両方を見る」と名乗って bit しか見ていなかった
- 「cpu」と名乗って CPU を測っていなかった
- 「クリック透過」の合格が、実は手前の窓に覆われていただけだった

`#[test]` の名前が主張していることを、そのテストが本当に assert しているか。
**関数の中身を定数に置き換えても緑のままになるテストは、何も証明していない。**

### 3. 測れなかったことを合格にしているもの

前提が満たされず早期 return するテストが、成功と区別できるか。
`0` が「無かった」なのか「数えられなかった」なのか、出力から分かるか。

### 4. 画面に出す言葉

- 測っていない効果を約束していないか
- 分からないものを「大丈夫」に混ぜていないか
- API 名、レジストリパス、GUID が画面に漏れていないか

### 5. 手で揃える必要のある2つの表

ActionParameters の `#[serde(rename)]`、ACL の toml、`invoke_handler`、
`parametersForAction`、`catalog.ts`、件数テスト、README、CHANGELOG。
**この形で2回壊している。** 抜けが残っていないか。

## やること

1. 見つけた欠陥を**全部一覧にする**（直す前に）
2. **直す**
3. 直したことを**測って示す**。既存の実機テストがあるならそれを走らせる。
   無くて必要なら足す
4. `docs/STATUS.md` の末尾に、見つけたものと直したものを書く

## 絶対に守ること

- **見つからなかったなら「見つからなかった」と書く。** 無理に何か直さない
- 直した結果を、**書けたことで証明しない**。読み直した数値で示す
- 新機能を足さない。件数（71）を増やさない
- 実機の設定を変えるテストは、`Drop` で必ず戻す
