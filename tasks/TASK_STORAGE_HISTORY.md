# タスク: 容量がいつ減ったか分かる履歴

`BRIEF.md` が契約。`docs/STATUS.md` を読むこと。
自分が書いた `docs/RESEARCH_FEATURES_ROUND3.md` の「2. 容量がいつ減ったか分かる履歴」を実装する。

## 作るもの

ドライブの空き容量と、利用者が選んだ既知フォルダーいくつかの合計サイズを、
ときどき記録して、**いつ減ったかを時系列で見せる。**

## 読み取り専用

**戻す対象が無い。** ファイルを消さない、動かさない、掃除しない。
Windows の設定を1つも変えない。

利用者が「履歴を消す」を押したときだけ、このアプリが持っている集計を消す。
それは OS の状態ではないので、**タイムラインにも「元に戻す」にも載せない。**

Action を増やさない。**71件のまま。**

## 名前とパスを保存しない

保存するのは**集計値だけ**。

- ファイル名を保存しない
- 個別のパスを保存しない
- 中身を読まない

保存するのは「このフォルダーの合計バイト数」「ファイル数」「採取時刻」まで。
**DB を検査して、名前もパスも入っていないことをテストで固定すること。**

## 走査の上限

`docs/STATUS.md` に、時間・件数・深さの固定 budget と
reparse point を追わない規則が既にある。**それを使う。**

- 上限に当たったら**打ち切る**
- 打ち切ったことを「完全な集計」として表示しない。**「途中まで」と出す**
- reparse point を追わない。循環で止まらない
- アクセス拒否は数えて、拒否された分があると表示する

## 原因を断定しない

「〇〇が容量を食っています」と書かない。
分かるのは「この期間にこのフォルダーの合計が増えた」まで。
**削除への導線を作らない。** 消すのは既存の一時ファイル削除の役目。

## 検証

自分で書いた「8) 外から効いたとどう測るか」をそのまま実行すること。

1. テスト専用フォルダーに**既知サイズ**のファイルを作る
2. 採取する。カテゴリの増分が実サイズの許容範囲内で一致することを確認
3. **別プロセスから**ドライブ空き容量を取り、方向と概算量が一致することを確認
4. ファイルを消す。次の採取で**逆方向へ戻る**ことを確認
5. reparse point を含む循環構造を作り、**追わない**ことを確認
6. 上限に当たったとき、**「完全」と表示しない**ことを確認
7. **DB を読み、ファイル名・パスが1つも入っていないことを確認**

`EVIDENCE:` 行に、各採取の数値を出すこと。
テスト用フォルダーは `Drop` で必ず消すこと。**利用者のファイルを触らない。**
