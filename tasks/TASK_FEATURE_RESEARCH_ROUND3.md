## 今回の焦点

**2回目で「表示専用の再判定」を2件試して、2件とも見送りになった。**
`SHGetSetSettings` 系は、値は書けても外部差を証明できない。
**同じ轍を踏む候補を出さないこと。** 出すなら、外部差の測り方まで具体的に書く。

そのうえで、次の3方向から探す。

### A. まだ触れていない領域（3件以上）

1回目・2回目で扱ったのは、入力・電源・表示・音声・タスクバー・Explorer・デスクトップ。
**まだ扱っていない領域**を探す。通知、時計・言語、ネットワークの表示、
ストレージ、印刷、クリップボード、資格情報の見え方、アクセシビリティなど。

BRIEF が禁じている領域（Defender、ファイアウォール、Windows Update、
昇格、pagefile、BCD、サービス一括停止、注入、ゲームファイル、任意スクリプト）は最初から出さない。

### B. 「まとめて戻せる」ことが効く場面（2件以上）

このアプリの芯は「1件ずつ戻せる」こと。
**その芯が競合より明確に効く場面**を探す。単発の設定変更ツールが勝てない場面。

例: 誰かに PC を貸す、配信する、子どもに使わせる、出張に持ち出す、
売る前に整える——といった**場面**から機能を出す。設定名から出さない。

### C. 既に持っている部品の組み合わせ（1件以上）

新しい Windows API を1つも足さずに成立するもの。
配色シーンがその形で成功した。**実装が安く、証拠がすでにある。**

## 各件について書くこと

1回目・2回目と同じ7項目。

1. 何ができるようになるか（利用者の言葉。設定名・API名を使わない）
2. なぜ必要か（**実在する声を URL と日付つきで。票数も。少なければ少ないと書く**）
3. 既存ツールはどうしているか、なぜ足りないか
4. Windows のどの公開手段で実現できるか（**文書化された API の URL**）
5. 元に戻せるか（**戻せないなら、そう書く**）
6. 実装の難しさと、いちばん危ないところ
7. この製品の芯と噛み合う理由

**さらに今回は各件に「8. 効いたことをどう外から測るか」を足すこと。**
測り方を書けない候補は、書けないと明記する。2回目の見送り3件はここが弱かった。

## 絶対に守ること

- 需要を盛らない。票が小さければ「限定的」と書く
- 効果を約束しない（速くなる・FPS・入力遅延）
- 戻せないものは guided（設定画面へ案内）に落とす
- 却下・保留も理由つきで書く
