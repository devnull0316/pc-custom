# タスク: ゲーム中の Shift 割り込みガードを実装する

`BRIEF.md` が最上位の契約。`docs/STATUS.md` に、このプロジェクトが踏んだ失敗が全部書いてある。
**特に「緑のテストは何も証明しない」の記録を読むこと。** 今回もそこが評価基準になる。

自分で書いた `docs/RESEARCH_FEATURES.md` の「1. ゲーム中の Shift 割り込みガード」を実装する。

## 作るもの

新しい Action を1つ。ゲーム中だけ、Shift の連打や長押しで
「固定キー機能」「フィルターキー機能」の確認画面が出ないようにする。

## 必ず守ること

**公開 API だけを使う。** `SystemParametersInfoW` の
`SPI_GETSTICKYKEYS` / `SPI_SETSTICKYKEYS` / `SPI_GETFILTERKEYS` / `SPI_SETFILTERKEYS`。
レジストリを直接書かない。未文書の手段を使わない。

**完全に元へ戻せること。** 適用直前に構造体の全フィールドを保存し、
ロールバックでそのまま書き戻す。**「既定値に戻す」ではなく「元の値に戻す」。**
利用者が独自の設定にしていたら、それを壊してはいけない。

**第三者の変更は上書きしない。** ロールバック時に現在値が自分の適用値と違っていたら、
上書きせず `ExternalConflict` で止める。既存の Action がどうやっているか読んで、同じ形にする。

**アクセシビリティ機能を無効化するのではない。** 消すのは「ショートカットで起動する挙動」だけで、
固定キー機能そのものを利用者から取り上げてはいけない。
実際にその機能を使っている人がいる。UI にもそう書くこと。

**自動適用の対象にしてよい。** これはモードで使ってこそ意味がある機能なので、
`auto_apply_eligible: true` にする。ただし `requiresExplorerRestart` は false（シェル再起動は不要）。

## 検証（ここが本題）

**書けたことを効果の証明にしない。** このプロジェクトはそれで6機能を無駄に出荷している。

`#[ignore]` の実機テストを書き、次を **別経路で** 確認して数値を出力すること。

1. 適用前の値を `SPI_GET*` で読む
2. 適用する
3. **もう一度 `SPI_GET*` で読み直して**、狙ったフラグだけが変わったことを確認する
4. ロールバックする
5. **もう一度読み直して**、全フィールドが元と一致することを確認する

出力は `EVIDENCE:` で始まる行に、前・後・戻し後の値を並べること。
自分が書いた値をそのまま assert するだけの自己充足テストは書かない。

**テストは必ず元の状態へ戻すこと。** panic しても戻るよう `Drop` を使う。
実機の利用者の設定であることを忘れない。

## 文言

日本語。**専門用語を出さない。** `SPI_SETSTICKYKEYS` や `STICKYKEYS` を画面に出してはいけない。
「Shift を5回押したときに出る確認画面を、このモードの間だけ出さないようにします」のように、
起きることを書く。BRIEF の9項目（何が変わる/おすすめ/現在/適用後/危険度/管理者/再起動/Update影響/戻せるか）
がすべて埋まること。
