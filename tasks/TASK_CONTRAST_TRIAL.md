# タスク: コントラストテーマを短時間試す

`BRIEF.md` が契約。`docs/STATUS.md` を読むこと。**特に今日の3件の取りやめ記録を読め。**
`docs/RESEARCH_FEATURES_ROUND3.md` の「7. コントラストテーマを短時間試す」を実装する。

## 今日3件、同じ理由で取りやめている

`separate_process`、`info_tips`、`time_format`。
**設定値は書けたが、外から見た表示が動かなかった。**

だからこのタスクは**測定を先に作れ。** 測れないなら実装しない。それも成果。

## 作るもの

高コントラスト表示を **15〜30秒だけ**試す。何もしなければ時間切れで元へ戻る。

## 必ず守ること

- 適用前に `HIGHCONTRASTW` の安定して取れる全フィールドと scheme 名を保存し、**その値へ戻す**
- **常時「戻す」を出す。** キーボードだけでも戻せること
- 時間切れで自動的に戻る。**戻らないまま残さない**
- 利用者が日常的に高コントラストを使っている場合（開始時点で既に有効）は、
  **何もしない。**「出番なし」と出す。人の常用設定を勝手に切り替えない
- 診断・推薦をしない。「あなたに合うテーマ」とは書かない
- 終了時、現在値が自分の適用値と違えば上書きしない

## 検証（ここが本題。先に作れ）

**「書けた」を「見た目が変わった」の証明にしない。**

自分で書いた「8) 外から効いたとどう測るか」を実行しろ。

1. **別プロセス**に標準のボタン・入力欄・リンクを出したテスト窓を作る
2. 適用前に、その窓のスクリーンショットから既知の前景／背景ピクセルを取る
3. 適用する
4. **同じ窓を測り直し**、ピクセルとコントラスト比が期待方向へ動いたことを確認する
5. `SystemParametersInfo` の `SPI_GETHIGHCONTRAST` も別経路として読む
6. 戻す
7. **新しく窓を作り直して**測り、開始前の値へ戻ることを確認する

`EVIDENCE:` 行に各時点のピクセル値とコントラスト比を出せ。

**ピクセルが動かないなら、そう出して落とせ。**
「読めた」ではなく「変わった」で判定しろ。今日それで2回間違えている。
`measured=false reason=...` を必ず出せ。**黙って return するな。**
