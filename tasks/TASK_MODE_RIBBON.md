# タスク: タスクバー上のモードリボン

`BRIEF.md` が契約。`docs/STATUS.md` の**オーバーレイの記録を全部**読むこと。
自分が書いた `docs/RESEARCH_FEATURES_ROUND2.md` の「候補2」を実装する。

## 作るもの

いまどのモードかを、タスクバーのすぐ上に細い色の帯で出す。
**PCカスタムが持つ自分のウィンドウ**を1つ置くだけ。

## Windows を1バイトも変えない

これがこの機能の性質。**OS の設定を変えないので、戻す対象が無い。**
タスクバーの状態も触らない。Explorer に注入しない。タスクバー内部を patch しない。
アプリを閉じれば消える。それ以外の消し方が要る作りにしない。

`SHAppBarMessage` は `ABM_GETTASKBARPOS` の**読み取りだけ**。`ABM_SETSTATE` は使わない。
appbar 登録（work area の予約）は初版ではしない。他のウィンドウを押し上げない。

## 既にあるもの

`src-tauri/src/windows/overlay_anchor.rs` に、
タスクバーの矩形・端・自動的に隠す状態の読み取りと、
`foreground_is_fullscreen()` が既にある。**再実装しないこと。**

ただし `foreground_is_fullscreen()` は「分からないときは true」に倒す作り。
オーバーレイを描かない側へ倒すためなので、**この用途にはそのままで正しい**。
迷ったら描かない。`docs/STATUS.md` の「自分で仕掛けた罠」の項も読むこと。

## 必ず守ること

- **クリックを透過する。** `WS_EX_TRANSPARENT | WS_EX_LAYERED | WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE`。
  リボンを押せてはいけない。下のものが押せなくなってはいけない。
- **全画面のときは出さない。** ゲーム、動画、判断できないときも出さない。
- **プライマリのタスクバーだけ。** 複数モニターへ広げない。
- **太さに上限を設ける。** 数ピクセル。設定で大きくできるようにしない。
- **常時アニメーションしない。** モードが変わったときだけ描き直す。
  `FPS に影響しない`とは書かない。常駐描画を最小にする。
- タスクバーが上・左・右にある場合と、自動的に隠す設定のときは、
  **邪魔にならないことを確認できないなら出さない。** 分からないなら出さない。
- Explorer が再起動したら位置を取り直す。`docs/STATUS.md` にその実験結果がある。

## 色

モードごとの色は**利用者が選ぶ**。既定を押し付けない。
色は「速そう」「強そう」ではなく、区別がつくことだけが目的。
選べる色は少数の固定候補にする。任意の色コードを画面から受け取らない。

## 画面

新しい画面を作らない。モード画面（`src/components/ProfilesView.tsx`）の中に置く。
**項目一覧に Action として増やさない。** これは Windows の設定ではない。

## 検証

**「描けた」を「見えている」の証明にしない。**

`#[ignore]` の実機テストで、次を数値で出すこと。

1. タスクバーの矩形を読み、リボンの想定位置を計算する
2. リボンのウィンドウを作る
3. **`GetWindowRect` で読み直して**、想定位置と一致することを確認する
4. **`WindowFromPoint` でリボンの中心を叩き**、リボン自身が返らないことを確認する
   （＝クリックが透過している）
5. 閉じる
6. **もう一度 `WindowFromPoint`** で、閉じたあと元のものが返ることを確認する

`EVIDENCE:` 行に、タスクバー矩形・リボン矩形・各時点の `WindowFromPoint` の結果を出すこと。
panic しても窓を破棄するよう `Drop` を使う。
