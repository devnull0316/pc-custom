# Totonoe プロダクト定義

## 1. この文書の位置づけ

本書は Task 1 の設計成果物であり、実装仕様ではなくプロダクト判断の基準を定める。判断が競合した場合は `BRIEF.md` を優先する。

Totonoe は「Windows を速くするツール」ではない。ゲーム、勉強、作業、普段使いという利用場面ごとに、Windows と周辺アプリの状態を、初心者でも結果から選び、安全に適用・復元できるアプリである。

## 2. 解決する不満

### 主対象

1. Windows の設定名やレジストリを知らないが、ゲーム中の通知や不要な表示を減らしたい人
2. 勉強・作業・配信など、場面ごとに同じ準備を繰り返している人
3. 設定を試したいが、「何を変えたか分からない」「元に戻せない」ことが不安な人
4. Windows Update 後に、以前の設定がまだ有効か判断できず困る人

### 現在の不満

- 設定画面は機能名中心で、得られる結果から探しにくい。
- 複数の設定画面、アプリ起動、状態確認を毎回手作業で行う必要がある。
- 一括最適化ツールは変更範囲が広く、根拠・現在値・復元方法が見えにくい。
- Web 上の「高速化」手順は、対象ビルド、危険度、戻し方が不明なことがある。
- ゲーム終了後やアプリのクラッシュ後に、一時変更が残ることがある。

## 3. 提供価値

Totonoe は、登録済みの小さな変更単位である **Action** を次の順序で扱う。

1. 現在状態と対応 Windows ビルドを検出する。
2. 変更内容、危険度、権限、再起動、Update 影響、復元可否を先に示す。
3. 変更前状態を保存する。
4. 適用して結果を検証する。
5. 履歴から1件だけ、または指定時点まで正確に戻す。

モードは Action の安全な組合せであり、任意スクリプトの実行単位ではない。ゲームプロファイルは、ゲームの起動・終了を条件にモードを一時適用し、そのプロファイルが変更した項目だけを戻す。

## 4. 表示と言葉の原則

### 4.1 結果を先に書く

| 避ける表示 | 採用する表示 |
| --- | --- |
| `HideFileExt = 0` | ファイルの拡張子を常に表示する |
| `AutoGameModeEnabled = 1` | Windows のゲームモードを有効にする |
| `SetThreadExecutionState` | このモード中は自動スリープを防ぐ |
| Explorer の設定変更 | 隠しファイルを表示して探しやすくする |

内部の API、CLI、レジストリ名は「変更方法の詳細」で説明し、カード見出しには使わない。

### 4.2 効果を誇張しない

- 「FPS爆上げ」「入力遅延ゼロ」「必ず軽くなる」は使用しない。
- Game Mode 等も性能向上を保証せず、「Windows のゲーム向け設定を有効にする」と説明する。
- 価値は「準備の再現」「邪魔の削減」「設定ミスの防止」「正確な復元」で表す。
- 測定していないメモリ、CPU、FPS の数値を製品説明に使わない。

### 4.3 不明を状態として見せる

状態は有効・無効だけではなく、次を区別する。

- `検出済み`
- `一部のみ検出`
- `未検出`
- `このビルドでは未検証`
- `組織のポリシーにより変更不可`
- `外部変更と競合`

未確認 API や未試験ビルドを「対応」と表示しない。

## 5. 機能カードの必須情報

すべての Action カードは、折りたたまれていても次の情報へ到達できなければならない。

| 項目 | 表示内容 |
| --- | --- |
| 何が変わるか | ユーザーが観察できる結果 |
| どんな人向けか | 利用場面と、不要な人の例 |
| 現在の状態 | 検出時刻を含む実測状態 |
| 適用後の状態 | 値ではなく結果を主表示 |
| 危険度 | 安全 / 注意 / 実験的と、その理由 |
| 管理者権限 | 不要 / 適用時のみ必要 |
| 再起動 | 不要 / Explorer 再読込 / アプリ再起動 / OS 再起動 |
| Windows Update | 影響が低い / 再検証対象 / 未検証 |
| 元に戻せるか | 復元対象と、復元できない副作用 |
| 変更方法の詳細 | 公開 API、公式 CLI、文書化レジストリ等 |

「安全」は絶対安全の意味ではない。例えば HKCU の文書化された値を変更し、変更前の型と生データを保存するため比較的安全、という根拠を併記する。

## 6. 主要な体験

### 初回

1. 対応 Windows ビルドと必要コンポーネントを確認する。
2. 禁止事項と「管理者権限は必要な Action の時だけ使う」ことを短く示す。
3. ゲーム、勉強、作業、普段使いの目的を選ぶ。
4. 推奨 Action を未選択の候補として提示し、勝手に適用しない。
5. 変更プレビュー、バックアップ、適用、検証結果を1画面で追えるようにする。

### 日常利用

- トレイ常駐中は UI 用 WebView を閉じ、ゲーム検知と復旧に必要な標準権限コアだけを残す。
- ゲーム開始時は、適用される Action と競合を通知する。
- ゲーム終了時は、そのセッションが所有する変更だけを逆順で戻す。
- 前回クラッシュによる未復元があれば、新しい自動適用より復旧を優先する。

### 変更タイムライン

各履歴から次を実行できる。

- この変更だけ戻す
- この時点まで戻す
- 変更前後と検証結果を見る
- 失敗項目だけ再試行する
- 個人情報を除いた診断ログを出力する

## 7. 信頼の約束

1. Defender、Firewall、Windows Update を無効化しない。
2. 任意 PowerShell、任意コード、出所不明バイナリを実行しない。
3. UI の文字列をシェルへ渡さない。
4. 変更前状態を保存できない Action は適用しない。
5. 検証できない成功を成功表示しない。
6. 復元時に外部変更を検出したら、黙って上書きしない。
7. 共有プロファイルに実行コード、ローカルパス、任意 URL を含めない。
8. AI は登録済み Action と型付きパラメータだけを提案し、適用はユーザー確認後に行う。

## 8. 非目標

- ベンチマークスコアや FPS の最大化
- Windows のセキュリティ機能を弱める「最適化」
- 汎用レジストリエディター、汎用シェル、スクリプトランナー
- ゲームプロセスへの注入、ゲームファイルの改変、アンチチート回避
- あらゆる Windows 設定を網羅するカタログ
- システム復元だけに依存する rollback

## 9. MVP の成功指標

数値はリリース判定用であり、性能効果の広告には使わない。

| 指標 | MVP 合格条件 |
| --- | --- |
| 復元正確性 | 対応 Action の正常系で、値の欠如・型・生データを含む往復試験が100%成功 |
| 途中失敗 | 故障注入試験で、適用済み項目が逆順 rollback され、失敗が隠れない |
| 状態検出 | 自動変更を許可する Action は適用前後を機械検出可能 |
| ビルド互換 | 対応表に載せる各 Windows ビルドで検出・適用・復元試験が完了 |
| 権限 | MVP の通常 Action は標準権限。昇格経路は任意コマンドを受理しない |
| 常駐負荷 | Task 2 の同一条件測定で定めた予算内。未測定値を合格扱いしない |
| クラッシュ復旧 | 各永続化境界で強制終了しても、次回起動時に未復元を検出できる |
| 説明可能性 | 適用前に、変更方法・復元対象・既知の制約を確認できる |
